# 从工程原型到有竞争力的参赛作品

本文件按所提供的《首届 AI 创新应用大赛通知》分析，定位为**赛道一、方向一：经贸与校园赋能智能体**。通知没有提供详细评分权重，本项目不自行编造分值，也不承诺奖项。

## 作品主张

**面向中国出口企业卖方，发现报价、订单和待签合同之间的交易条件变化，用双方原文与企业策略支持判断，并通过人工处理、修订复查和版本归档形成闭环。**

答辩主线围绕同一笔交易展开：原报价 → 不利变更 → 审查证据 → 人工要求修改 → 修订版本 → 复查 → 审批归档。静态 Pages 是作品入口；真实能力演示应来自运行中的工作台，并展示至少一个真实模型推理过程。

2026-10-20 更新：已完成 CUAD 九类条款的公开专家标注子集 LoRA 试训、冻结测试与实验 Adapter 交付，见 [实际训练报告](TRAINING_REPORT.md)。这补上了专项微调的技术试验；正式外贸风险数据、专业复核、多种子验证和 Agent 专用工具集成仍未完成。下表中的“正式专业 Adapter”指达到业务验收条件的版本。

## 目前最重要的不足

| 优先级 | 不足 | 对竞争力的影响 | 处理方式 |
|---|---|---|---|
| P0 | 没有封存、独立复核的专业效果测试集 | 无法证明语义风险判断的准确性和实际收益 | 组织专业复核，按来源家族隔离；固定输入后比较规则、原始模型、优化提示词和专业模型 |
| P0 | 缺少真实用户任务与外部复核 | 产品价值仍主要由自建演示支持 | 邀请 6–10 名国际商务学习或实务人员，交叉安排人工与 AI 两种处理方式，同时测漏检、误报和用时 |
| P0 | 自由文本、跨条款及复杂表格能力未系统验证 | 评委更换合同后可能表现不稳定 | 建立独立模板、长条款、不同付款触发条件、复杂表格及困难负例；暴露覆盖不足并允许人工补充 |
| P1 | 原版本缺少明确的修订变化清单与策略编辑入口 | 闭环可用，但难以在演示中看清前后变化 | 本次新增修订对照、历史快照与策略编辑；新版本重新处理和审批 |
| P1 | 原版本商品核对只覆盖行金额，没有逐 SKU 比较 | 多商品交易的专业特色不够鲜明 | 本次新增显式 SKU 数量/单价核对，单位、币种及重复匹配的人工确认分支 |

| P1 | 扫描件尚无完整 OCR | 图片与扫描材料的可用性有限 | 后续集成按页 OCR，并单独评测识别和表格定位；比赛鼓励多模态，但通知未规定必须包含语音或图片 |

| P2 | 尚无正式专业 Adapter | 不能宣称已完成方向二的领域微调作品 | 方向一可先使用本地原始模型；审核数据成熟后再训练，避免为了“有微调”而制造无效实验 |

## 本轮可核查的工程改进

1. **修订复查**：保存上一轮完整审查的关联，展示新增、再次检出、未再检出；策略、参考资料、知识快照或覆盖范围变化单独标明。未再检出不等于系统确认解决。
2. **历史追溯**：可选历史审查；原文与字段使用该次快照，历史结果只读。旧审批、旧处理意见不会复制到新版本。
3. **企业策略**：界面修改预付款下限和最长账期；版本化保存并要求重审。
4. **商品核对**：显式 SKU 精确关联；跨文档比较数量、同币种单价；单位不同或缺少、重复 SKU、币种不同等进入人工核验。没有实现自由文本商品匹配、自动单位换算或总价费用归集。
5. **模型证据关口**：跨文档差异必须有至少两个输入文档的可匹配引句；位置由后端从原块生成，模型不能伪造页码；拒绝超出字段契约的抽取。内容是否构成实质差异仍需专业评测。
6. **依据透明**：界面展示企业阈值、原创复核清单、官方来源链接、版本和适用条件。检索命中仅表示相关参考，不能当成本案法律适用已确定。
7. **工程回归**：提供 28 个场景的 API 闭环回归，涵盖字段变化、策略、SKU、金额、日期、缺失资料及 TXT/DOCX/XLSX/PDF；CI 保存逐场景结果。它是同源模板的受控回归，不能当作独立效果测试。

## 接下来真正决定竞争力的工作

### 第一关：让独立材料经得住现场试用

选择与演示模板不同的 20 组英文贸易材料。覆盖正常交易、单因素条件变化、多条款关联、材料不足、扫描件和多商品表格。由具有相关知识的复核者建立预期结果、关键证据与可接受建议。记录所有失败，不将重复模板数量作为材料多样性。

验收时分别检查解析、事实、语义判断、证据、人工操作和最终状态。先修复最常见的失败类别，再扩大到原计划的 100 个端到端案例。模型评测使用标准文本，系统评测从原文件开始，避免把 OCR 错误算作模型能力差异。

### 第二关：用同一批材料证明增益

至少比较“规则”“规则＋原始模型”“规则＋优化提示词”；若完成专业微调，再加入“规则＋专业模型”。知识检索开关单独对照。固定模型版本、输入、提示词、规则、知识快照与参数。

正式报告给出风险 Macro-F1、关键风险 Recall/Precision、引用匹配率、任务成功率、延迟和失败类型；按案例家族计算置信区间。没有专业金标准之前，只报告工程回归，不能宣称达到原计划的 85%/90%/95% 指标。

### 第三关：让用户而非开发者证明价值

邀请 6–10 名有国际商务背景的试用者，使用难度匹配、顺序交叉的任务。独立复核处理质量；同时看完成时间、漏检、误报、证据定位是否方便及修改建议是否可用。未经专业许可的客户材料不得作为公开 Demo。

### 第四关：把证据组织成好演示

5–8 分钟建议：问题与用户 40 秒；上传与校对 60 秒；跨文档与 SKU 证据 90 秒；模型语义条款与依据 60 秒；修订复查与审批 90 秒；评测、失败边界和自行运行入口 60 秒。可按实际时长删减，保留完整真实操作。

演示三个场景：正常、矛盾、信息不足。至少一个展示修订后复查；至少一个展示专业人员认为重要、规则无法直接判断的语义条款。视频中的模型结果、耗时和硬件需要真实记录。

## 使用本轮新增能力

- 上传含显式行项目的报价和合同，例如：
  `SKU: CUP-01 | Quantity: 10 | Unit: pcs | Unit price: USD 12 | Line total: USD 120`
- 启动审查，查看商品变化；在右栏展开“策略与检索参考”，查看来源和适用条件。
- 在事实栏展开“调整策略”，保存后重新审查；对照面板会明确标记策略变化。
- 上传修订合同后再次审查，查看新增、再次检出和未再检出；通过审查历史切换前一轮。
- 逐项记录本次处理意见并人工审批。旧处理意见不自动继承。
- 复现 CPU 工程回归：`python scripts/benchmark_agent.py --output .data/agent-regression.json`。

## 仍需人和资源才能完成的事项

专业标签复核、真实用户试用与专家评价需要相应人员参与，代码不能替代。没有通过审核的数据时不启动训练；需要训练或新模型推理服务时，先确认服务器与获配 GPU，再检查显存和计算进程，发现占用就停止启动流程，不终止他人进程。
