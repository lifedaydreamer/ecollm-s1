# 当前版本检查与修复

日期：2026-10-20。基于 main `31be2c6` 检查。修复范围为业务状态、字段冲突、审批恢复和模型复现；未修改已发布训练权重、冻结测试集或原训练成绩。

## 已定位并修复

| 问题 | 触发与影响 | 修复 |
|---|---|---|
| 同字段模型事实被截掉 | 同一次抽取返回 30% 和 50%，追加第一条后会拒绝第二条，规则误以为取值唯一 | 以抽取前已有字段为判断依据，保留本次所有候选；冲突进入待核验 |
| 校对后状态仍为已归档 | 同时赋值时先序列化旧状态，修订号增加但案例状态没有变为草稿 | 先更新状态再保存，旧审批仍绑定旧修订 |
| 重复执行审批可能重复归档 | 两个请求通过校验后在执行阶段重放；已完成任务缺少执行入口防护 | 审批校验与恢复共用锁，已批准/过期任务不重复执行 |
| 中断重试携带旧批准状态 | 持久化状态中保留 approved/approval 或旧错误，容易混淆重试与人工批准 | 新执行显式清除批准状态与旧错误；无人工恢复请求不能归档 |
| 独立推理不自动核验制品 | 用户选错或修改基座、Adapter 后仍可能尝试加载 | GPU 加载前校验基座文件、Adapter 权重和关键配置 |
| 专项 Adapter 误接业务服务 | CUAD 输出为 status/evidence，通用业务接口需要 facts/findings | 业务服务在加载 GPU 前拒绝已知 CUAD Adapter，指向专用入口 |
| 权重下载和源码选择容易混淆 | 发布自动 Source code 包关联旧应用基线；手动找权重容易遗漏许可或校验 | 新增标准库下载工具，固定 ZIP 与文件校验值，仅安装指定权重/配置/许可，不解压任意路径、不覆盖已有目录 |
| README 的训练进度表述过时 | 一处已写完成试训，另一处仍笼统说训练未完成 | 明确区分已完成 BF16 LoRA 试训与尚未完成的正式外贸实验 |
| 数据准备允许覆盖已封存输出 | 重复执行数据转换可能覆盖旧划分和清单 | 已存在非空数据目录时拒绝写入，要求新版本目录 |

## 验证方式

新增回归覆盖：模型同字段冲突、归档后人工纠正、重复审批执行、重试不得自动批准、恢复后旧错误清理、错误模型身份、配置和权重被修改、输入格式、安装拒绝覆盖、ZIP 校验失败、任意归档路径不被提取。

实际发布 ZIP 已在无 Torch 的环境完成离线安装和哈希校验。服务器隔离环境的后端 31 项测试、28/28 场景业务回归和静态预览一致性检查通过。CI 还会执行真实公开 ZIP 下载、安装、再次校验、前端生产构建和全新 Docker Demo 闭环。新增模型制品检查均为 CPU 验证，不需要占用共享 GPU。

服务器直接访问 GitHub 资产下载出现读取超时，属于当前网络路径限制；工具会提供具名 ZIP 离线安装方式，并保持相同的包及权重校验。未改用未核验的镜像源。

## 仍未完成的能力

- CUAD 模型尚未作为专用条款工具接入业务工作流；当前修复会明确拒绝把它误当通用 Adapter。
- 正式外贸付款/交付/跨文档数据需要专业复核；三种子、优化提示词强基线及独立业务效果尚待完成。
- OCR、复杂表格字段对应、完整混合检索和长合同覆盖尚未完成原计划的验收。
- 真实用户试用和多用户权限/队列仍待建设，当前交付定位为自行运行的单工作区原型。

这些能力缺口需要单独实现和验证，不能用代码修复或现有 CUAD 分数冒充完成。
