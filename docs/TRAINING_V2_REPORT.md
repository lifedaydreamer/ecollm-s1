# CUAD V2：实际执行记录与未完成项

2026-10-20。**本轮未完成 V2 训练，未发布新的 V2 Adapter。** 已发布的 V1 模型及其原冻结测试结果仍可复现；不能将下面的验证分数当作新版训练成绩。

## 已完成

1. 用固定源包复现 V1 数据转换，711 / 54 / 72 三份文件与原实验哈希完全相同。
2. 生成 V2 训练 1,921 条、原验证 54 条、新来源确认 106 条、旧测试回归 72 条；确认集覆盖 62 个此前全部 V1 分区均未使用的来源家族。
3. CPU 前置检查通过；训练样本最长 1,593 tokens，未截断证据。核对原基座及旧 Adapter 身份。
4. 冻结候选配置与选择门槛，完成两种提示词下的 V1 验证推理。

| 原 V1 模型，原验证 54 条 | 原提示词 | 加入 CUAD 类别定义 |
|---|---:|---:|
| 证据 token F1 | 84.11% | 84.42% |
| 条款存在判断 Macro-F1 | 92.28% | 93.47% |
| 回答内全部引句原文匹配率 | 96.30% | 96.30% |

证据 F1 仅提升 **0.31 个百分点**，不能称为显著模型提升。这个强基线将用于后续检验训练收益。相同的批量解码重现了 V1 原验证分数。

## 中止原因与资源记录

两组验证输出完成后，验证进程在退出时停留于内核不可中断的 D 状态，等待位置为 `uvm_gpu_release`。后续训练控制器尚在等待该子进程结束，因此 **V2 训练未开始，新确认集也未评测**。

在持续观察到同一阻塞后，仅核验并取消了本任务的待执行训练控制器、通知本任务守护退出，保留原服务恢复流程。没有重置 GPU、修改驱动或停止其他人的计算任务。自己的驱动回收进程也不能被当成已释放显存。

共享 GPU 采用明确授权的 GPU 2、24GiB 任务上限、22GiB Torch allocator 上限。取消前 90 个监测样本中，本任务观察峰值 **9,112 MiB（8.90GiB）**，最少空闲 **48,756 MiB**。这些是采样观察值，不能称为对瞬时硬件显存的数学保证。[实际资源审计](validation/cuad-v2-attempt/blocked-audit.json)。

恢复原模型服务时发现启动环境遗漏基座目录，已修正恢复工具，并按原基座、原接口及同样共享资源限制重新启动。业务、模型健康状态以部署现场最后一次独立检查为准。

## 仍需完成

GPU 驱动资源回收恢复后，在新的实验输出目录重跑 [预注册协议](TRAINING_V2_PROTOCOL.md)：先完成基座强提示词验证，再训练候选 A / 必要时 B，通过验证门槛后才做三种子及新来源确认。不得根据尚未评测的确认集调整配置。

当前能确认的显著工程收益是 [英文付款句式覆盖提升](PAYMENT_IMPROVEMENT.md)。正式外贸风险数据、完整合同评测、Agent 的专业模型工具适配和真实用户收益仍需独立完成；CUAD 条款抽取分数不能替代这些验收。
